## Decisions

Record answers to the "Decide" points in PHASES.md here.

| Phase | Question | Decision |
|-------|----------|----------|
| 1 | `bool` as qty? | Rejected (`QuantityError`) |
| 1 | Numeric strings (`"3"`) as qty? | Accepted, whitespace stripped; Unicode digits (`"٣"`) work too |
| 1 | `2.0` as qty? | Accepted if whole (`2.0`, `"2.0"`); `2.5`, nan, inf rejected |
| 1 | Blank qty (`None`, `""`)? | Treated as missing -> 1 |
| 1 | Index in error messages | 0-based position in the input list |
| 2 | Last row of a sheet | Always padded to `cols` cells (Word tables need even rows) |
| 2 | `fill_last` with `new_page_per_record` | Pads every incomplete sheet, not only the final one |
| 2 | `skip` with `new_page_per_record` | Applies to the first sheet only |
| 2 | `interleaved` with `new_page_per_record` | Rejected (`ValidationError`) |
| 2 | No records | No pages (`[]`) |
| 3 | Backends | segno, python-barcode, Pillow are core deps (light, prebuilt wheels, no system libraries) |
| 3 | Registry | Module-level dict + `register(replace=)`, `get`, `names`; not pyvocabulary (one small lookup) |
| 3 | Payload type | `str` only, non-empty; ints raise `PayloadError`. Coercion (e.g. `str(item.id)`) is for phase 4 to decide |
| 3 | QR encoding | UTF-8, no ECI header; error level M (PNG boosts it when it fits, ZPL cannot). Changed from segno's default L in phase 4 |
| 3 | Linear images | Bars only, no human-readable text (PNG and SVG). PNG drawn by qrbar, `scale` px per module, 50 modules tall |
| 3 | EAN-13 input | 12 digits (check computed) or 13 (check verified); ASCII digits only |
| 4 | Template owns `^XA`/`^XZ` or renderer wraps? | Template owns them. qrbar adds `^CI28` after the first `^XA`, `^PQ{qty}` before the last `^XZ`; a template `^PQ` is a `TemplateError` |
| 4 | Where `dpi` comes from | Template: `{% set dpi = 300 %}` before the first code; default 203 |
| 4 | Non-string payloads | Ints become strings; bools, floats, others raise `PayloadError` |
| 4 | `^`/`~` in plain `{{ }}` values | `ValidationError` (ZPL injection); code payloads are hex-escaped with `^FH_` |
| 4 | Code sizes | `size_mm` (both), `width_mm`, `height_mm`. Width / module count, floored, capped at 10 dots; too narrow raises. No width: round(dpi / 100) dots per module. No height: 50 modules |
| 4 | Errors while rendering a record | `RecordError(index, error)`, a `ValidationError`; the original is `.error` |
| 4 | Jinja | `StrictUndefined` (missing fields raise), `trim_blocks`, UTF-8 templates (BOM allowed) |
| 5 | `per_item` with qty | One document per record; template gets `item` and `items` (its qty copies) |
| 5 | Code size in docx | The code only, no quiet zone, same as ZPL; the template leaves white space |
| 5 | Default docx size | 0.25 mm per module (matches ZPL's default); linear codes 50 modules tall |
| 5 | Image resolution | PNG scale chosen for >= 600 dpi at the printed size |
| 5 | Escaping | docxtpl autoescape on: `&`, `<` in data are XML-escaped |
| 5 | Errors | `per_item`: `RecordError`. `sheet` / `paged` render all records at once, so errors carry no record index; Jinja errors become `TemplateError` |
| 5 | QR with different `width_mm` / `height_mm` | Image is stretched (ZPL ignores height for QR); use `size_mm` for QR |
| 6 | Default `mode` | `paged`: works for every template with no extra arguments; `sheet` needs `sheet=SheetSpec(rows, cols)` |
| 6 | Copy limit | `max_copies=10_000` total per call by default (`None` disables); over it is a `ValidationError` before rendering, ZPL included |
| 6 | Options that do not apply | `ValidationError`: `sheet`/`options` outside `mode="sheet"`, `collate` with `per_item`, ZPL with `mode="sheet"` or interleaved |
| 6 | Collation in the API | One `collate=` kwarg for `paged` and `sheet`; in `sheet` it overrides `options.collate` |
| 6 | Joined ZPL | Blocks concatenated as-is (`b"".join`), byte-identical to the `per_item` blocks |
| 6 | Return type | `@overload`: `mode="per_item"` -> `list[bytes]`, otherwise `bytes` |
| 6 | Public names | `qrbar.__all__`: `render`, `render_code`, `SheetSpec`, `SheetOptions`, the type aliases, `DEFAULT_MAX_COPIES`, the exceptions. Modules keep their names (no `_` rename); `qrbar.symbologies` stays public for custom handlers |
| 7 | Arabic font source | Bundled IBM Plex Sans Arabic Regular (SIL OFL 1.1, Arabic + Latin, 236 KB) as package data, `fonts/OFL.txt` beside it; callers override with `render(font=ttf_bytes)`. Reading package data is not caller I/O |
| 7 | `text()` API | `text(value, size_mm=3)`; `size_mm` is the font size (`^A0N,h,h` for Latin, Pillow size for Arabic). The Arabic graphic is the font's full line height, so it is taller than `size_mm` |
| 7 | When to rasterize | Only text containing Arabic (U+0600-06FF, 0750-077F, 08A0-08FF, FB50-FDFF, FE70-FEFF); everything else stays native `^A0` with `^FH` escaping, so `text()` also makes `^`/`~` safe |
| 7 | Direction | python-bidi default: base direction from the first strong character (Arabic first -> RTL line) |
| 7 | Raster | 1-bit, no anti-aliasing, uncompressed `^GFA` hex. Field anchored top-left at the template's `^FO`; no right alignment or wrapping |
| 7 | Missing extra | Latin `text()` works without it; Arabic raises `ValidationError` naming `pip install qrbar[arabic]` (wrapped in `RecordError`) |
| 7 | `font` with docx | `ValidationError` (a docx uses its own fonts) |
| 8 | 2D backend | zxing-cpp (prebuilt wheels, ~1.8 MB, no system libraries) as a core dependency for Data Matrix, PDF417, Aztec; no treepoem |
| 8 | Scope | Only `upca`, `datamatrix`, `pdf417`, `aztec`; others when a label needs them |
| 8 | Protocol | `module_count` replaced by `module_size(payload) -> (width, height)` in modules; ZPL's default height is `module * height`, so PDF417 keeps its natural ratio |
| 8 | UPC-A | python-barcode, 11 digits or 12 with a verified check digit (shares the EAN-13 check); ZPL `^BU` |
| 8 | Data Matrix | Always square (ZPL `^BX` default); size chosen by the printer; `~` sent as `~d126` because `^BX` reads `~` as an escape |
| 8 | PDF417 | ZPL `^B7` pinned to zxing-cpp's columns, rows and security level so the printed size matches; `height` is the total, split per row |
| 8 | Aztec | ZPL `^BO` with default error correction and size; no quiet zone (Aztec needs none) |
| 9 | PDF API | Separate `docx_to_pdf(docx, *, soffice=None, timeout=120)`; `render()` stays free of processes and temp files |
| 9 | `qrbar[pdf]` extra | None: the converter needs no Python packages, only LibreOffice |
| 9 | Errors | `ConversionError(QrbarError)`, not a `ValidationError`: LibreOffice missing, failing or timing out is an environment problem. Non-docx input is a `ValidationError` |
| 9 | Process handling | Private LibreOffice profile per call (parallel-safe); output to a log file, not a pipe; on timeout the whole process tree is killed (`taskkill /T` on Windows, process group on POSIX) |
| 10 | License | GPL-3.0-or-later, as in all the author's packages; the font's OFL listed as a second licence file |
| 10 | CI | GitHub Actions: lint job (ruff, format, mypy), tests on Python 3.12-3.14 (Ubuntu) and 3.12 (Windows), one job installs LibreOffice for the real PDF test, a build job uploads `dist/` |
| 10 | Publishing | Left to the author: no remote, no commits, and publishing needs their PyPI credentials |

## Notes

- 2026-11-09: Phase 0 done. Config follows pyflowstep (ruff `select = ["ALL"]`,
  line length 100, `exceptions.py` with built-in-compatible bases). Type checker
  is `mypy --strict` (pyflowstep uses pyright); tests are type-checked too, so
  test functions need `-> None`.
- 2026-11-09: Phase 1 done. `qrbar/records.py`: `Record`, `parse_records`,
  `parse_quantity`, `expand`, `collate`; `QuantityError` in `exceptions.py`.
  No upper limit on qty yet: a huge qty from untrusted input makes `expand`
  build a huge list. Decide a cap before the public API (phase 6).
- 2026-11-09: Phase 2 done. `qrbar/layout.py`: `SheetSpec`, `SheetOptions`,
  `layout_sheet` -> `list[Page]` (`Page = list[Row]`, `Row = list[Cell]`,
  `Cell = Record | None`). `layout_sheet` takes parsed records and expands them.
- 2026-11-09: Phase 3 done. `qrbar/symbologies/` (`base.py` protocol + registry,
  `qr.py`, `linear.py`) and `qrbar/image.py` (`render_code`). python-barcode's
  ImageWriter made bars 1 px off at most scales (and crashed at scale 1), so
  linear PNGs are drawn from `build()` patterns; a test asserts exact widths.
  python-barcode has no type hints (mypy override in pyproject). zxing-cpp 3 can
  also *generate* DataMatrix, PDF417, Aztec: candidate backend for phase 8.
- 2026-11-09: Phase 4 done. `qrbar/zpl.py` (`render_zpl`), `module_count` and
  `to_zpl` on each symbology, `zpl_field` / `payload_text` in
  `symbologies/base.py`, `TemplateError` and `RecordError`. Not verified on a
  printer or a ZPL viewer (e.g. Labelary): `^BC` automatic mode with `>` in the
  data, and `^FH` inside `^BQ` fields, are worth checking on real hardware.
- 2026-11-09: Phase 5 done. `qrbar/docx.py` (`render_docx_sheet`,
  `render_docx_paged`, `render_docx_per_item`), `quiet_zone` option on
  `to_png`, `require_positive` in `_checks.py`. New deps: docxtpl (pulls
  python-docx, lxml). docxtpl has no type hints (mypy override). Sheet/paged
  errors have no record index; phase 6 could pre-check payloads per record if
  that matters for web apps.
- 2026-11-09: Phase 6 done. `qrbar/api.py` (`render`, `Mode`, `TemplateKind`,
  `DEFAULT_MAX_COPIES`), public exports in `qrbar/__init__.py`, end-to-end
  tests in `tests/test_api.py` using only `import qrbar`. Kind sniffing is
  "zip -> docx, else ZPL", so a non-docx zip (xlsx) reaches the docx renderer
  and fails there as a `TemplateError`.
- 2026-11-09: Phase 7 done. `qrbar/arabic.py` (`has_arabic`, `rasterize`,
  `to_gf`, `default_font`), `text()` in `zpl.py`, `font=` on `render_zpl` and
  `render`, `arabic` extra (arabic-reshaper 3.1, python-bidi 0.6), bundled font
  in `src/qrbar/fonts/` (checked in the built wheel). Fixture
  `tests/fixtures/arabic_text.png` (made by `make_text_fixture.py`) was checked
  by eye; a Pillow/FreeType update may move pixels and need a re-check. Not
  verified on a printer: the `^GF` field and its size next to `^A0` text.
- 2026-11-09: Phase 8 done. `qrbar/symbologies/matrix.py` (Data Matrix,
  PDF417, Aztec on zxing-cpp), `UpcaSymbology` in `linear.py`. zxing-cpp moved
  from dev to core deps; the dev group now includes `qrbar[arabic]` so a plain
  `uv sync` keeps the Arabic libraries. Not verified on a printer: whether
  `^BX`/`^BO` pick the same symbol size as zxing-cpp (Aztec error correction
  differs: zxing-cpp ~47%, ZPL default 23%), UTF-8 data in `^BX`/`^B7`/`^BO`
  under `^CI28`, and the `~d126` escape. Worth checking in Labelary.
- 2026-11-09: Phase 5 follow-up. Exporting the sample sheet through Word showed
  a blank page after every full A4 sheet: 8 x 37 mm rows leave 1 mm, and the
  page-break / trailing paragraphs did not fit. `make_docx_fixtures.py` now
  makes them 1 pt tall (`tiny()`); 21 stickers + skip 2 = 1 page, 49 copies =
  3 pages in Word. The XML tests could not see this; the PDF page-count test
  can. The README tells template authors the same.
- 2026-11-09: Phase 10. README rewritten (user asked for rich examples): every
  Python block runs in `tests/test_readme.py` (FastAPI, Django and own-font
  blocks are marked `# needs:` and skipped). `ruff format` also formats the
  README's Python blocks. LICENSE (GPLv3), `[project.urls]`, licence files and
  classifiers in `pyproject.toml`; sdist and wheel checked. CI workflow written
  but never run. PyPI not published.
- 2026-11-10: Phase 9 code done: `qrbar/pdf.py` (`docx_to_pdf`, `find_soffice`),
  `ConversionError`. Error paths tested with a fake soffice (including a real
  timeout that kills the process tree, checked on Windows). The real
  LibreOffice test is still unrun: `scoop install libreoffice` failed twice
  (download of the 358 MB MSI aborted / timed out). Install LibreOffice
  (libreoffice.org) and run `uv run pytest tests/test_pdf.py -rs`; CI's Linux
  3.12 job also installs it.
- 2026-11-10: Phase 9 done. With LibreOffice 26.8.2 (scoop) the real test
  passes: 25 copies -> 2 pages; 49 copies -> 3 and the skip-2 sample -> 1, the
  same as Word. scoop puts no `soffice` on PATH, so its install folder is now
  one of the default locations. Each conversion takes ~11 s here, mostly a
  fresh LibreOffice profile per call (kept for parallel safety); a shared
  profile would be faster if bulk PDF jobs need it.
